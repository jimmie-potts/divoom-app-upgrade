## Why

[Issue #33](https://github.com/jimmie-potts/divoom-app-upgrade/issues/33) connects the delivered shared state and exact RGB renderer to explicit user-controlled display participation. Collection must continue without allowing task events to replace media or revive retired writes.

## What Changes

- Add a monitor panel, explicit session/project filtering over existing neutral identities, shared label editing and notice dismissal, with the exact selected RGB preview.
- Coordinate persistent Monitor/Media intent, paused recovery and explicit activation through the existing player and adapter queue.
- Expose a finite protected Pixoo integration v1 extension with revision/request guards and current-state snapshots, without widening released controller API 1.0.
- Use the qualified complete RGB method and configurable 1000 ms minimum submission interval; preserve simulator-default startup and source-only delivery.

## Capabilities

### New Capabilities

- `agent-monitor-controls`: selected view, explicit display ownership, guarded integration commands, monitor UI and inactive restart recovery.

### Modified Capabilities

None. Existing playback, shared-state, released controller v1 and transport contracts remain intact; the new capability composes them.

## Impact

Server monitor/control services, player-owned uploads, shared API schemas and browser controls; focused fake-clock, injected-transport, API and browser verification. Product/monitoring documentation and ADR 0018 will describe the policy. A linked Hub guide companion will reconcile ownership diagrams and delivered facts. No dependencies, device configuration, live state, installation or public-site publication change.
